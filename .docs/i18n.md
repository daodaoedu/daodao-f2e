# 國際化 (i18n) 規範

本專案支援多語言國際化，使用 Google App Script 進行翻譯資料管理，並採用 JSON 格式存儲翻譯文本。

## 架構概述

```
shared/config/locales/
├── zh-TW.json          # 繁體中文（預設）
├── en.json             # 英文
└── ...                 # 其他語言
```

## 翻譯文件結構

### 檔案組織
- 翻譯文件放置於 `shared/config/locales/` 目錄
- 檔名格式：`{語言代碼}.json`（如：`zh-TW.json`, `en.json`）
- **⚠️ 重要：JSON 文件不可直接編輯，僅能透過 `pnpm fetch:i18n` 指令更新**

### JSON 結構規範

**層級限制：最多支援兩層嵌套結構，避免過度深層**

```json
{
  "common": {
    "title": "島島阿學",
    "description": "學習資源共享平台",
    "submit_button": "提交",
    "cancel_button": "取消"
  },
  "features": {
    "auth_login": "登入",
    "auth_logout": "登出",
    "project_create": "建立專案",
    "project_edit": "編輯專案"
  },
  "pages": {
    "home_hero_title": "歡迎來到島島阿學",
    "about_mission_title": "使命"
  }
}
```

**❌ 避免過深的嵌套結構**：
```json
{
  "features": {
    "auth": {
      "forms": {
        "login": {
          "title": "登入表單"  // 太深！
        }
      }
    }
  }
}
```

**✅ 推薦的扁平化結構**：
```json
{
  "features": {
    "auth_login_form_title": "登入表單",
    "auth_forgot_password": "忘記密碼？"
  }
}
```

## 命名規範

### Key 命名原則
1. **兩層結構限制**：最多支援兩層嵌套（如：`common.title` 或 `features.auth_login`）
2. **語意化命名**：使用描述性的英文單詞，複合詞以底線分隔
3. **一致性**：相同概念在不同地方使用相同的 key
4. **扁平化優先**：避免深層嵌套，優先使用扁平化結構

### 範例命名
```json
{
  "common": {
    "title": "島島阿學",
    "save_button": "儲存",
    "delete_button": "刪除",
    "edit_button": "編輯",
    "loading_status": "載入中...",
    "success_message": "成功",
    "error_message": "錯誤"
  },
  "features": {
    "auth_login_title": "會員登入",
    "auth_forgot_password": "忘記密碼？",
    "project_create_button": "建立專案",
    "project_edit_form_title": "編輯專案"
  },
  "pages": {
    "about_page_title": "關於我們",
    "about_mission_section": "使命",
    "home_hero_title": "歡迎來到島島阿學"
  }
}
```

## 使用方式

### 在 FSD 架構中的應用

#### Shared 層
```typescript
// shared/lib/i18n.ts
export const getTranslation = (key: string, locale: string = 'zh-TW') => {
  // 翻譯邏輯實作
}

// shared/config/i18n.ts
export const defaultLocale = 'zh-TW'
export const supportedLocales = ['zh-TW', 'en']
```

#### Features 層
```typescript
// features/auth/components/LoginForm.tsx
import { useTranslation } from '@/shared/lib/i18n'

export const LoginForm = () => {
  const { t } = useTranslation()
  
  return (
    <form>
      <h2>{t('features.auth.login_form_title')}</h2>
      <button>{t('common.actions.save')}</button>
    </form>
  )
}
```

#### Widgets 層
```typescript
// widgets/layout/ui/Footer.tsx
import { useTranslation } from '@/shared/lib/i18n'

export const Footer = () => {
  const { t } = useTranslation()
  
  return (
    <footer>
      <p>{t('common.footer_copyright', { year: new Date().getFullYear() })}</p>
    </footer>
  )
}
```

## 資料管理流程

### Google App Script 整合
1. **資料來源**：翻譯資料透過 Google Sheets 管理
2. **自動同步**：使用 Google App Script 自動同步翻譯資料
3. **環境變數**：需設定 `NEXT_I18N_URL` 指向 Google App Script 端點

### 更新流程
**⚠️ 重要：本地 JSON 文件為只讀，僅能透過以下指令更新**

```bash
# 獲取最新翻譯資料（唯一更新方式）
pnpm fetch:i18n
```

**禁止操作**：
- ❌ 直接編輯 `shared/config/locales/*.json` 文件
- ❌ 手動修改翻譯內容
- ❌ 透過其他方式更新翻譯文件

**正確流程**：
1. 在 Google Sheets 中更新翻譯內容
2. 執行 `pnpm fetch:i18n` 同步到本地
3. 提交更新後的 JSON 文件到版本控制

## 最佳實踐

### 1. 結構設計
- **兩層限制**：嚴格遵守最多兩層嵌套的結構限制
- **扁平化優先**：優先使用扁平化的 key 命名，避免深層嵌套
- **語意清晰**：key 名稱要能清楚表達內容用途和位置

### 2. 翻譯品質
- **準確性**：確保翻譯內容準確傳達原意
- **一致性**：同一概念在不同地方使用相同翻譯
- **語境適應**：考慮不同語言的文化背景和使用習慣

### 3. 技術實作
- **類型安全**：為翻譯 key 建立 TypeScript 類型定義
- **效能考量**：避免在 render 中動態載入翻譯資料
- **錯誤處理**：提供翻譯缺失時的 fallback 機制

### 4. 維護策略
- **版本控制**：翻譯文件納入版本控制
- **審查流程**：翻譯變更需經過審查
- **測試覆蓋**：為翻譯功能編寫測試
- **只讀原則**：嚴格遵守本地 JSON 文件只讀的原則

## 參數化翻譯

### 支援變數插值
```json
{
  "common": {
    "welcome_message": "歡迎 {username}！",
    "item_count": "共 {count} 個項目",
    "footer_copyright": "島島阿學 © 2022 - {year}"
  }
}
```

### 使用範例
```typescript
// 基本用法
t('common.welcome_message', { username: '小明' })
// 輸出：歡迎 小明！

// 數字參數
t('common.item_count', { count: 5 })
// 輸出：共 5 個項目

// 日期參數
t('common.footer_copyright', { year: 2024 })
// 輸出：島島阿學 © 2022 - 2024
```


### Next.js App Router 整合
```typescript

  children,
  params: { language }
}: {
  children: React.ReactNode
  params: { language: string }
}) {
  return (
    <html lang={language}>
      <body>{children}</body>
    </html>
  )
}
```

## 常見問題與解決方案

### 1. 翻譯缺失
```typescript
const t = (key: string, fallback?: string) => {
  const translation = getTranslation(key)
  return translation || fallback || key
}
```

### 2. 複數形式處理
```json
{
  "messages": {
    "notification_count": {
      "zero": "沒有通知",
      "one": "1 個通知",
      "other": "{count} 個通知"
    }
  }
}
```

### 3. RTL 語言支援
```css
/* 為 RTL 語言添加樣式支援 */
[dir="rtl"] .text-left {
  text-align: right;
}
```

## 檢查清單

開發新功能時的 i18n 檢查項目：

- [ ] 所有使用者可見文字都已提取為翻譯 key
- [ ] 翻譯 key 遵循命名規範（扁平化、語意清晰）
- [ ] 結構不超過兩層嵌套限制
- [ ] 透過 Google Sheets 添加翻譯內容
- [ ] 執行 `pnpm fetch:i18n` 同步翻譯資料
- [ ] 提供所有支援語言的翻譯
- [ ] 測試不同語言下的 UI 佈局
- [ ] 處理翻譯缺失的情況
- [ ] 考慮文字長度變化對 UI 的影響
- [ ] 未直接編輯本地 JSON 文件
