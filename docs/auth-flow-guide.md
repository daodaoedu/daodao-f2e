### 登入方式

| 登入方式 | 說明 | 狀態 |
|---------|------|------|
| Google OAuth | 使用 Google 帳號快速登入 | ✅ 已實作 |
| Apple Sign In | 使用 Apple ID 登入（iOS App） | ✅ 已實作 |
| Email + 密碼 | 傳統帳號密碼登入 | ❌ 目前禁用 |

### 登入觸發點

用戶可在以下情境觸發登入：

1. **主動登入**：點擊導覽列的「登入」按鈕
2. **功能觸發**：嘗試使用需要登入的功能（如：收藏、發文、報名活動）
3. **受保護頁面**：直接訪問需要登入的頁面

## 新用戶 Onboarding 流程

### 整體流程

新用戶首次登入後，需完成 Onboarding 流程才能使用完整功能。


**目的**：建立基本個人檔案

| 欄位 | 必填 | 說明 | 驗證規則 |
|------|------|------|---------|
| Email | ✅ | 從 OAuth 提供者帶入，不可修改 | - |
| 名字 | ✅ | 顯示名稱 | 最多 50 字 |
| 生日 | ✅ | 用於年齡驗證 | 需滿 16 歲 |
| 帳號 ID | ✅ | 個人專屬網址 | 3-15 字，僅英數字 |
| 個人標語 | ✅ | 自我介紹 | 最多 150 字 |

## 頁面與狀態對照

### 路由結構

#### 前端路由

| 路由 | 頁面名稱 | 用途 |
|------|---------|------|
| `/auth/login` | 登入頁面 | 登入入口 |
| `/auth/callback` | OAuth 回調頁 | OAuth 登入後的中繼頁 |
| `/auth/onboarding` | Onboarding 頁面 | 新用戶資料填寫 |
| `/auth/verify-email/pending` | 驗證等待頁 | 等待用戶驗證 Email |
| `/auth/verify-email` | 驗證結果頁 | 顯示驗證成功/失敗 |

#### 後端 API 路由

| 路由 | 說明 |
|------|------|
| `/api/v1/auth/*` | 認證相關（登入、登出、驗證） |
| `/api/v1/users/*` | 用戶管理（CRUD、偏好設定） |
| `/api/v1/me/*` | 當前用戶快捷路由 |

### 用戶狀態與功能權限

### 常見錯誤情境

| 情境 | 處理方式 | 用戶提示 |

| Apple 登入取消 | 返回登入頁 | 「登入已取消」 |
| Apple ID Token 驗證失敗 | 顯示錯誤 | 「Apple 登入失敗，請稍後再試」 |
| 驗證連結過期 | 顯示重發選項 | 「驗證連結已過期，請重新發送」 |
| 驗證連結已使用 | 顯示重發選項 | 「驗證連結已被使用」 |
| 網路錯誤 | 顯示重試選項 | 「網路連線異常，請檢查後重試」 |
| Token 過期 | 觸發重新登入 | 「登入已過期，請重新登入」 |
| Authorization code 過期 | 重新進行 OAuth | 「授權已過期，請重新登入」 |

### 重新發送驗證信限制

- **冷卻時間**：60 秒
- **每日上限**：5 次
- **用戶提示**：顯示剩餘等待時間

### 跨裝置/跨瀏覽器登入

- 驗證連結在任何裝置/瀏覽器點擊皆有效
- 點擊驗證後，原本的等待頁面會自動偵測並更新狀態
- 支援多 Tab 同步（一個 Tab 驗證成功，其他 Tab 自動更新）

### Token 處理

| 項目 | 說明 |
|------|------|
| Token 類型 | JWT (JSON Web Token) |
| 過期時間 | 7 天 |
| 儲存方式 | HTTP-only Cookie（優先）或 Authorization header |
| Cookie 名稱 | `auth_token` |
| Cookie 選項 | `httpOnly: true`, `secure: true`, `sameSite: 'none'` |

#### Token 刷新機制

- Token 接近過期時，前端可呼叫 `POST /api/v1/auth/refresh` 延長有效期
- 刷新後會生成新 token 並更新 Cookie
- 刷新記錄會加入 `refreshedAt` 時間戳

### App OAuth 流程（Authorization Code）

iOS/Android App 使用額外的 code 交換機制：

```
1. App 完成 OAuth 認證
2. 後端生成一次性 authorization code（5 分鐘有效）
3. 重定向到 App：myapp://oauth?code=xxx&state=xxx
4. App 呼叫 POST /api/v1/auth/token { code }
5. 後端驗證 code 並回傳 token
6. Code 消耗後失效（防止重放攻擊）
```

### 安全機制

| 機制 | 說明 |
|------|------|
| CSRF 保護 | OAuth 使用 state 參數和 nonce 驗證 |
| HTTP-only Cookie | 防止 JavaScript 存取 token |
| 重放攻擊防護 | Authorization code 只能使用一次 |
| 速率限制 | 驗證信發送有 60 秒冷卻和每日上限 |
